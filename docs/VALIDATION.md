# 0.2.3 回归验收

日期：2026-10-18。Windows x64，官方 WebView2 SDK 1.0.4258.31，Runtime 155.0.4283.60。

## 修复内容

- 旧代码只在穿透状态注册和处理 `~ / 5 / 6`，导致默认浏览器状态无效。现已删除穿透状态，窗口显示且热键开启时始终注册播放控制。
- 沉浸从 `9` 移到 `8`，`9` 完全不占用。
- 沉浸布局完成后执行原生定位，用 `GetWindowRect` 验证实际贴边，并在后续布局、状态轮询后维持吸附。
- `8` 现在直接对齐实际显示器底部；旧版“最近任意边缘”不再用于沉浸，普通拖动吸边也不再将任务栏上沿当作屏幕底部。检查明确要求窗口底部等于显示器底部。
- `7` 隐藏时注销播放和沉浸按键，仅保留主键盘及数字小键盘的 `7` 作为恢复键。隐藏期间入口也拒绝控制指令。

## 已通过

12 项视频桥接测试和 59 项真实应用检查。

真实应用检查使用生产 `AppController` 绑定，并用 Windows `SendInput` 按下、释放实际按键；不再用伪造 `WM_HOTKEY` 代替注册及键盘链路。输入前核对前台窗口确实为独立测试窗，否则失败退出，不向用户其他应用注入输入。

本版 59 项检查完整通过。Windows 若拒绝测试进程自行取得前台，测试会安全中止；可以使用 `-InteractiveFocus` 并正常激活专用测试窗后继续，不更改系统前台锁定规则。

覆盖：普通浏览器状态下真实 `~ / 5 / 6` 控制、视频五秒跳转和暂停恢复、真实 `7` 隐藏/恢复、隐藏后 `~ / 5 / 6 / 8` 可被另一窗口注册、隐藏时测试文本框正常接收数字输入且视频状态不变、恢复后的播放键重新生效、真实 `8` 进入沉浸、无边框视频铺满、真实 HWND 贴边及等待状态轮询后仍保持、`8` 退出恢复界面和大小位置、可操作鼠标表面、`9` 未占用、关闭释放按键、无视频和冲突时恢复入口。

结果在 `artifacts/app-self-test.json`。普通界面和沉浸图分别保存为 `artifacts/app-ui.png`、`artifacts/app-immersive.png`。

底部专项检查覆盖：从更靠近顶部或侧边的位置仍贴底、横向越界钳制、负坐标显示器、普通底边吸附阈值、真实窗口底部坐标、网页布局及状态轮询后的持续贴底、横竖视频比例改变后贴底、`7` 隐藏恢复后贴底。沉浸固定在进入时选中的显示器，避免改宽高后误选相邻屏幕。

Bilibili 官方文档确认其播放器可能使用 `bwp-video`；该路径做了标准媒体接口能力检查及模拟测试。当前公开样例实查使用原生 `video`；未获得真实 `bwp-video` 播放样例。

## 未覆盖

实际游戏的特殊输入、管理员权限游戏、独占全屏、不同显卡及混合 DPI 跨屏人工操作。上述桌面真实键盘测试不代表所有游戏都已实测。
